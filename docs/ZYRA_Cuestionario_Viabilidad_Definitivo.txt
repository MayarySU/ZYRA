======================================================================
INSTRUCCIONES PARA EL AGENTE
======================================================================

Este archivo sustituye, como FUENTE FUNCIONAL DEL CUESTIONARIO, las plantillas seed simplificadas creadas durante el desarrollo técnico del módulo de Viabilidad.

NO MODIFIQUES ESTE ARCHIVO DURANTE LA IMPLEMENTACIÓN.

Antes de cambiar código:
1. Lee el archivo COMPLETO.
2. Inspecciona el esquema, motor de reglas, editor de plantillas, evidencias, versionado, RLS, offline/outbox y pruebas actuales.
3. Compara la implementación existente contra este documento.
4. Devuelve un plan corto de compatibilidad.
5. NO IMPLEMENTES hasta que el usuario apruebe ese plan.

REGLAS DE INTERPRETACIÓN:

- Conserva exactamente cada CODIGO.
- No elimines, combines, resumas ni sustituyas preguntas.
- No inventes opciones, condiciones, unidades, evidencias, umbrales ni consecuencias.
- ETAPA solo puede ser previabilidad o ingenieria en este documento.
- Una pregunta OBLIGATORIA solo bloquea el cierre cuando está ACTIVA.
- Una pregunta inactiva por ACTIVACION no debe bloquear la entrega.
- EVIDENCIA = foto significa fotografía.
- EVIDENCIA = documento significa archivo/documento.
- EVIDENCIA = foto_o_documento admite cualquiera de los dos.
- Si EVIDENCIA_OBLIGATORIA = si, una pregunta activa no se considera completa sin evidencia válida y sincronizada.
- Si EVIDENCIA_OBLIGATORIA contiene una condición, la evidencia solo es obligatoria cuando dicha condición se cumple.
- UNIDAD debe modelarse como metadato estructurado; no debe depender únicamente del texto visible.
- La especificación original usa el concepto "medicion". En el modelo actual puede representarse como numero + unidad, siempre que se conserve la semántica.
- Previabilidad captura condiciones observables, datos preliminares y documentación de sitio.
- Previabilidad NO sustituye dictámenes estructurales, eléctricos, legales o de CFE.
- Ingeniería contiene diseño final, documentación técnica y validaciones especializadas.
- No conviertas una observación en no_apto solo para hacerla compatible con el motor.
- No conviertas una regla de validacion_especializada en no_apto.
- No inventes umbrales profesionales.
- lamina_espesor_mm es un dato. NO existe un umbral universal de 0.7 mm autorizado.
- La ausencia de protección de falla por arco, en la condición definida, requiere validación eléctrica especializada; NO produce no_apto automático.
- Si el esquema actual no soporta UNIDAD, EVIDENCIA, EVIDENCIA_OBLIGATORIA o EVIDENCIA_INSTRUCCION, amplía el modelo mediante migración/versionado. No escondas esos datos dentro de TEXTO o AYUDA.
- Las versiones históricas/publicadas deben permanecer inmutables. El cuestionario definitivo debe publicarse como nuevas versiones.
- Si una semántica de este archivo no puede representarse exactamente con el motor actual, REPÓRTALA antes de inventar un mapeo.

DECISIÓN APROBADA SOBRE AFECTA_EVALUACION
======================================================================

AFECTA_EVALUACION es descriptivo y se deriva de las reglas reales de la versión de plantilla.
No se almacena como segunda fuente autoritativa.

Las siguientes preguntas quedan explícitamente con AFECTA_EVALUACION = no porque no son
referenciadas directamente por ninguna regla, aunque algunas controlen ACTIVACION de preguntas hijas:

- grua_lineas_tension
- riesgo_social_medidas
- arboles_cantidad
- lamina_calibre
- asbesto_confirmado
- goteras
- material_oxidado
- sombras

ACTIVACION por sí sola no significa que una pregunta afecte la evaluación.
